# グラレコ画像の作り方

`<会議>/digest/grareco.html` を書き、`digest.py image` で PNG(4K と 1920)にする。写真や絵画調の画像は使わず、HTML と SVG のイラストだけで組む。日本語が崩れず、あとから文言を1か所直すのも簡単だからである。

**この手引きは doodle スタイル(手描き風)の書き方。** business スタイルの部品と構成は `references/styles.md` にある。共通するのは「2. 内容の選び方」「5. 収まりの調整」「6. 確認のしかた」。

雛形は `digest/lib/grareco-base.html`(`init` か `image` で同期される)。作例は skill フォルダの `assets/examples/study/grareco.html`(発表3本の勉強会)。新しい会議は、雛形か作例をコピーして中身を書き換えるところから始めるのが早い。CSS とスクリプト部分はそのまま使える。

## 目次
1. 全体の構成
2. 内容の選び方
3. HTML の部品
4. イラスト(既存の一覧と、追加の描き方)
5. 収まりの調整
6. 確認のしかた

## 1. 全体の構成

- 本体は `body { width:1840px; height:1035px }`。この設計サイズを 4K(3840x2160)と 1920x1080 に拡大して出す。文字を大きくしたいときは、文字サイズを上げるのではなく設計サイズを小さくする(1760x990 にすれば全体が約5%大きくなる)。16:9 は保つ。
- 上にヘッダー(タイトル、開催情報、ひとこと吹き出し、章の一覧)。下に章の数だけ列を並べる(`main` の `grid-template-columns`)。章は、勉強会なら発表ごと、会議なら議題ごと。3つなら3列。2つなら2列にして各列の内容を増やす。4つ以上は2段組にするか、1つあたりを絞る。
- 会議のグラレコでは、「決定事項」と「TODO(担当・期限)」を独立した列か、目立つ帯にまとめる。読む人が最初に探すのはそこだからである。
- 列ごとにテーマ色を決める(`c1` coral、`c2` magenta、`c3` orange。足りなければ teal / blue / purple / green)。スライドがあるなら、その基調色に合わせると動画と画像で印象が揃う。動画の `episode.yaml` の `color` と同じにする。

## 2. 内容の選び方

### 2a. 書く前に抜き出す

HTML を書き始める前に、議事録(`minutes.md`)から次を箇条書きにする。全体のバランスが先に見え、詰め込みすぎや抜けに気づける。会議全体で1回、章(発表・議題)ごとに1回。

| 項目 | 目安 | 置き場所 |
|---|---|---|
| 主題 | 1つ | タイトル、章の見出し |
| 主要メッセージ | 章ごとに 1つ(+補助 3つまで) | 章の最初のブロック。`big` か `xl` |
| 数値・固有名詞 | 出てきたもの全部(確認済みのものだけ) | 蛍光ペン、`xl` |
| 時系列・手順 | あれば | 矢印でつなぐ工程、タイムライン |
| 対立・比較 | あれば(案 A と案 B、前と後、○と△) | 左右に並べる、○△ の記号 |
| 引用・ひとこと | 章ごとに 1〜2 | 吹き出し |
| 結論・次の行動 | 1〜3 | 下部の決定事項・ネクストアクション、章の最後 |
| 質疑 | 面白かったもの 1〜2 | `qa` |

**1章は「主メッセージ1つ+補助3つ」を上限の目安にする。** それより多いときは、議事録に任せて削る。グラレコは全部を書く場所ではなく、全体像を5秒で掴ませる場所。1 章あたり 6〜8 ブロックになると、読み物としては成立しても目安より多い。それ以上は増やさない。

### 2b. 構造を選ぶ

抜き出した内容の形に合わせて、章ごとに構造を決める。既定は上から下へ読む縦積みだが、内容によって次を使い分ける。

| 構造 | 向く内容 | 部品 |
|---|---|---|
| 時系列 | 経過、手順、移行 | 矢印でつないだ工程、タイムライン(`.route` / `.tl`) |
| 関係図(中央放射) | 1つの主題から派生する論点、システム構成 | 中央に主題、周りに要素、`data-pts` の矢印 |
| 比較 | 案の比較、前後、長所と短所 | 2つの `card` を横に並べる、○△ |
| 階層 | 全体と部分、分類 | 入れ子の `card`、`chip` の列 |
| 循環 | 繰り返す工程、改善のループ | 円環に並べた `step` と矢印 |
| マトリックス | 2軸の整理 | 2×2 の `card` |

同じ会議でも章ごとに構造が違ってよい。全部の章が同じ縦積みになっていたら、どれか1つは別の構造にできないか考える。見た目の変化が読む側の目印になる。

### 2c. 選び方の心得

その場にいなかった人が「何の話で、何が決まり、何が面白かったか」を掴めることを優先する。

- 課題 → やったこと → 結果、論点 → 意見 → 結論、という流れが見えるものは、その順に並べて矢印でつなぐ。
- 数字(件数、時間、金額)と固有名詞は大きく、蛍光ペン(`<mark>`)か `xl` クラスで目立たせる。
- 印象的なひとことは吹き出し(`bub`)にする。
- 質疑で面白かったやり取りは、列の最後に Q マーク(`qa`)で1〜2個。
- 笑いどころや人柄が出たところを落とさない。要約としての正確さだけだと、読んで楽しくない。

載せる事実は、共通ルール(`rules.md`)の「事実の扱い」に従ってスライドか音声で確認する。

## 3. HTML の部品

作例の CSS が定義しているクラス。組み合わせて使う。

| 部品 | 書き方 | 用途 |
|---|---|---|
| セクションの札 | `<span class="tag">課題</span>` | ブロックの見出し |
| 強調(中) | `<div class="big">…</div>` | 小見出し、結論 |
| 強調(大) | `<span class="xl">735件</span>` | 数字、キーワード |
| 蛍光ペン | `<mark>…</mark>` | 文中の強調 |
| 色文字 | `<em>…</em>` | 用語 |
| 注記 | `<div class="note">…</div>` | 補足(細い手書き体) |
| 手描きの枠 | `data-box="塗り,線"` を要素に付ける | カード、チップ、吹き出し。`data-box="white,coral"`、塗りだけなら `data-box="pink,none"`。線の太さ `data-sw`、角丸 `data-r`、線の荒さ `data-rough` |
| チップ | `<span class="chip" data-box="white,coral" data-sw="1.8"><span>QA</span></span>` | 並べる短い語 |
| 吹き出し | `<span class="bub" data-box="white"><span>…</span></span>` | 発言 |
| カード | `<div class="card" data-box="white,coral" data-sw="2.4">…</div>` | まとまりを囲む |
| 横並び | `<div class="row">` / `<div class="row top">` | アイコンと文を並べる。`grow` で残り幅を取る |
| 矢印 | `<span class="ar">→</span>` | 流れ |
| 質疑 | `<span class="qa">Q</span>` | 質疑の印 |
| イラスト | `<i data-ico="名前" data-s="60"></i>` | `data-s` は大きさ(px)。`data-rot` で傾き、`data-seed` で線のゆらぎを変える |

注意点:

- `data-box` を付けた要素の直下に文字を直接書くと、枠の塗りの下に隠れる。`<span>` か `<div>` で1段包む(作例のチップや吹き出しを参照)。
- Yusei Magic(見出し用の手書き体)は「5.4」のような数字と小数点の字形が読みにくい。モデル名やバージョン番号は `font-family:'Zen Maru Gothic'; font-weight:900` にする。
- 経路や年表のように位置を決めて置く図は、作例の `.route`(絶対配置の点と、`data-pts` で引く手描きの線)を参考にする。

## 4. イラスト

### 既存の一覧(`lib/doodle.js`)

会議全般: `calendar` `check` `bulb` `target` `chart` `people` `clock` `flag` `warning` `question` `note` `rocket` `mic` `laptop` `docs` `checklist` `browser` `network` `map` `robot` `coin` `building`

過去の会議で描き足したもの: `tablet` `kitchen` `waffle` `pizza` `asagao` `caterpillar` `spray` `grasshopper` `seeds` `bento` `book` `piano` `tomb` `plane` `train` `ferry` `nowifi` `sleepless` `suitcase` `backpack` `parcel` `hotel` `torii` `standing` `stamp`

人物: `face` `sloth`

`face` は引数で描き分ける: `data-a="髪の色,服の色,髪型"`(髪型は `long` / `bob` / `short`)。似顔絵にはせず、記号的な顔にとどめる。本人がアバターを使っているなら、それに寄せてよい(作例のナマケモノ)。議題だけで発表者がいない章は、顔の代わりに議題を表すイラストを置く。

### 追加の描き方

内容に合うイラストは会議ごとに違うので、たいてい数個は新しく描く。`<会議>/digest/icons.js` に書く(`lib/` は自動生成で上書きされるので、そこには書かない)。

```js
Object.assign(ICONS, {
  // 100x100 の枠に描く。p はペン。塗りは C.色名 か "#rrggbb"
  mug(p) {
    p.rr(24, 30, 44, 50, 6, C.white);                         // 角丸の四角(x, y, 幅, 高さ, 角丸, 塗り)
    p.path("M68 40 Q88 42 86 58 Q84 70 68 68", null, { strokeWidth: 2.6 });  // 取っ手(塗りなしの線)
    p.steam(38, 24); p.steam(52, 22);                         // 湯気
  },
});
```

ペンのメソッド: `rect(x,y,w,h,塗り,opt)` `rr(x,y,w,h,r,塗り,opt)` `circ(cx,cy,直径,塗り,opt)` `ell(cx,cy,w,h,塗り,opt)` `line(x1,y1,x2,y2,opt)` `path(d,塗り,opt)` `poly([[x,y],…],塗り,opt)` `curve([[x,y],…],opt)` `dot(cx,cy,直径)` `text(x,y,文字,サイズ,色)` `sparkle(x,y,大きさ,塗り)` `steam(x,y)`。`opt` には `stroke` `strokeWidth` `roughness` を渡せる。

色名(`C.〜`): `coral` `pink` `yellow` `green` `leaf` `teal` `sky` `blue` `navy` `purple` `magenta` `orange` `brown` `sand` `gray` `white` `skin` `red` `cream` `lav`。

描き方のこつ:

- 単純な図形 3〜8 個で組む。rough.js が線を揺らすので、単純な形のほうが手描きらしく見える。細部を描き込むと小さく表示したときに潰れる。
- 後ろにあるものから順に描く(あとに描いたものが上に重なる)。
- 新しいイラストは、まとめて一覧で描画して形を確かめてから本体に置く。確認用の HTML を `digest/work/` に作り、`ICONS` の各名前を `icon(名前, 110, seed)` で並べて描画すればよい。

## 5. 収まりの調整

描画すると、列ごとの下の余白がコンソールに出る(`col 1 余白(px): 12`)。

- 余白が大きい列は内容を足すか、イラストを大きくする。余白が 12px(=パディング分)なら、ちょうど収まっている。
- 「内容がはみ出している」と出たら、文を短くする、ブロックを減らす、設計サイズを大きくする(1920x1080 にすると全体が約4%小さくなる)のどれか。
- 変なところで折り返す文は、`<br>` を入れるか、言い回しを短くする。1〜2文字だけが次の行にこぼれるのは見栄えが悪い。

## 6. 確認のしかた

- `digest.py image` のあと、出力の 1920 版を Read で見て全体のバランスを確認する。
- 4K 版をパネルごとに切り出して拡大し、文字を読む(PIL の `Image.crop` でよい。パネル数+下部の 1 枚まで。それ以上は読まない)。誤字、折り返し、枠からのはみ出し、イラストと文字の重なり、字形の読みにくさは、拡大しないと見えない。
- 載せた数字と固有名詞を、スライドのフレームや文字起こしともう一度突き合わせる。
- **5秒テスト**: 1920 版を一瞬だけ見て、タイトル・章の数・各章の主メッセージが目に入るか。入らなければ、主メッセージの文字を大きくするか、周りを減らす。
- **同種は同じ記号**: 質疑は全部 `qa`、決定は全部 ○、未決は全部 △、のように、同じ種類の要素が同じ見た目になっているか。章ごとに表現が揺れていたら揃える。
- **余白**: 列の下に余白が残っていても、埋めるために内容を足さない。文字を少し大きくするか、そのままにする。
