# 共通ルール(どの会議にも効く)

実際に指摘されたこと、失敗したことをまとめたもの。理由も書いてあるので、書かれていない場面では理由から判断する。
プロジェクト共通のルール(`<プロジェクト>/digesta.md`)と会議ごとのルール(`<会議>/digesta.md`、`<会議>/digest/rules.md`)がこれと食い違うときは、そちらを優先する。

## 事実の扱い

- **録画の音声と画面(スライドなど)が正、自動生成のメモや要約は参考。** 自動のメモは数値・製品名・日付を間違える。ある勉強会では、スライドの「gpt-5.4」をメモが「GPT-4o」、次回日程を2年前の日付で書いていた。成果物に載せる数値・固有名詞・決定事項は、画面のフレーム(`sheet` や `grid`)か、精密な文字起こし(`asr.py windows`)で確認する。
- **文字起こしだけが根拠の人名・固有名詞は、載せたうえで「要確認」として報告する。** 自動文字起こしは人名を別人の名前に聞き違える。ある発表者の名前が、会議メモでも Whisper でも、参加していた別の人の名前になっていた例がある。エージェント側では気づけない種類の誤りなので、ユーザーに一覧で見せて確認してもらうしかない。録画の参加者表示や話者名のラベルは、本文中の人名より信頼できる。
- **素材で確認できないことは書かない。** 次回の日程、連絡先、担当者、期限など、素材にないことを補わない。
- 元素材(録画、文字起こし、メモ)は変更しない。素材側の誤りを見つけたら、直さずに報告する。

## 表記とトーン

- 人名・用語の表記は、`digesta.md` の用語集(会議フォルダ > プロジェクト)とルールに従う。指定がなければ、素材での呼ばれ方に合わせて「姓+さん」か「呼び名+さん」に揃える。
- **コピーは上から目線にしない。** 「参加できなかった人もこれ1枚で追いつこう!」は「上から目線すぎる」と言われ、「これ1枚でバッチリ!」に直した。見る人に何かを課す言い方より、成果物の良さを言う言い方にする。
- 発言を字幕や引用にするときは、言い間違いやフィラーを整えるが、言っていないことは足さない。文脈の補足は丸括弧で入れる。

## 使わない素材

- 開発環境、顧客や案件のコンテンツ、パスワード・トークン・個人情報が映る画面は、切り抜きにもグラレコにも使わない。発言者が「見なかったことにして」と言っている箇所は確実に外す。
- **ビジネスの会議(開発定例、打ち合わせ)では、顧客名や案件名が画面や発言に出るのは許容する。** カンバンや Issue 一覧に顧客名があるからといって、切り抜き領域を狭めたり、その区間を避けたりしない(ユーザー指示 2026-10-07。開発定例で、Issue 本文だけが映るよう切り抜きを狭めたのを「無理に切り抜かないで」と止められた)。外すのは、局所的な個人情報(住所、電話番号、個人のメールアドレス、本人確認書類など)が映る・読まれる箇所と、パスワードやトークンが映る画面。顧客名を伏せる必要がある会議なら、プロジェクトか会議のルールにそう書いてあるはず。
- 人事、評価、契約金額など機微な話題は、ルールに指示がなければ、載せる前に確認事項として報告に挙げる。
- 動画のカットを決めたら、その区間のフレームを実際に見て、映っているものを確かめる。音声だけで決めない。

## 外部送信と秘密情報

- 議事録と画像は、外部に何も送らずに作る。
- 動画で Gemini TTS / Lyria を使うと、ナレーション原稿と音楽の指示が Google に送られる。プロジェクトの `external_api` が `allow` になっていない限り使わない。未確認(`ask`)ならユーザーに尋ね、答えを `digesta.md` の設定に記録する。
- API キーは `.env`(会議のフォルダ → プロジェクトのフォルダの順に探す)の `GEMINI_API_KEY`、なければ環境変数、`~/.config/digesta/gemini.env` の順に読む。どこから読んでいるかは `digest.py status` に出る(キー本体は出ない)。
- `.env` や API キーのファイルは、`digest.py status`、`wc -c`、`ls -l` だけで確認する。`cat`、`awk`、`grep` など、中身や一部を表示するコマンドは使わない。「キー名と長さだけ」を出すつもりのコマンドがキー本体を表示し、ユーザーにキーを再発行させたことがある。キーをチャットに貼らせない。

## 配布先での再エンコード

- Google ドライブや Slack は、動画をプレビュー用に再エンコードする(ドライブは 360p / 720p / 1080p、音声は AAC-LC 128 kbps 44.1 kHz)。このとき**音声パケットの時刻どおりに音を組み直す**。手元のプレーヤーは時刻を無視してサンプルの並びどおりに再生するので、時刻が壊れていても手元では気づけない。
- 2026-10 に発生。本編カットを作るときの `loudnorm` が、先読みのために冒頭約 3 秒の音声パケット時刻を乱す(0.019 秒間隔で詰め込み、その後 2.3 秒飛ぶ)。サンプルも映像より数十 ms 短くなる。ドライブでは各カット開始の約 0.8 秒後から 2.3 秒、声が消えた。BGM や音質は無関係だった(BGM なし版だけ無事に見えたのは、結合の経路が違って時刻が付け直されていたため)。
- 対処: `digest.py video` は、カットごとに音声を「時刻を捨ててサンプルの並びどおりに読み、映像の長さちょうどに切りそろえて」1 本の WAV(`work/voice.wav`)にしてから混ぜる。**時刻を信じてそろえる処理(`aresample=async=1`)は使わない。** 壊れた時刻どおりに声を捨てて無音を埋めるので、欠落を焼き込む(一度これで「直した」つもりになった)。
- 出来上がりは毎回検査する: 音声パケットの間隔がすべて 1024、音と映像の長さが一致、時刻どおりに再生しても音量の並びが変わらない。どれかに外れたら出力しない。
- 調べ方の教訓: 「プレビューでだけ音がおかしい」ときは、配布先が実際に作ったストリームを取り寄せて元と比べるのが最短。次に `ffprobe -select_streams a -show_entries packet=pts,duration` で時刻の間隔を見る。完成動画だけでなく、材料のカット単体も見る。無音検出だけで「直った」と判断しない(BGM が鳴っていると無音にならない)。問題の区間の音量を、材料と突き合わせる。

## 規約

- VOICEVOX を使うなら、動画内か投稿文にクレジット表記(例: `VOICEVOX:四国めたん`)が必要。社内限定・非公開でも例外はない。`credit` 設定が空だとビルドが止まる。
- Gemini TTS と Lyria にはクレジット表記の義務が見当たらなかった(2026-10 時点で規約を確認)。

## 不具合を直すとき

「ドライブのプレビューで声が消える」不具合では、原因を 2 回取り違え、直っていないのに直ったと報告した。同じことをしないための決まり。

- **「ある条件のときだけ起きない」だけで原因を決めない。** BGM を外すと直ったが、原因は BGM ではなかった(結合の経路が変わって時刻が付け直されていた)。原因だと言う前に、その条件がなぜ効くのかを仕組みで説明できるか確かめる。説明できないうちは「〜のとき起きない。原因は未特定」と報告する。
- **初期設定や共通ルールを、確認なしに変えない。** 回避策として既定値を変えたくなったら、提案して了承を取る。このときは `bgm` の既定を勝手に `none` にして、ユーザーに止められた。
- **直したら、報告された症状そのものが消えたかを確かめる。** 「18 秒付近で声が聞こえない」なら、18 秒付近の声の音量を材料(区切りのファイル)と突き合わせる。間接的な指標(パケットの時刻が等間隔、無音検出なし)が正常でも、症状が残っていることがある。BGM が鳴っている区間は無音として検出されない。
- **確かめていないことを「直った」と書かない。** 配布先でしか確かめられないものは、「手元で確認できたこと」と「配布先での確認はこれから」を分けて報告する。
- **配布先でだけ起きる問題は、配布先が作ったデータを取り出して元と比べる。** 聴き比べ用のファイルを何本も作ってユーザーにアップしてもらう進め方は、ユーザーの手間が大きく、原因にも届かなかった。Google ドライブなら、プレビュー用のストリームをブラウザ経由で取れる。
- **完成品だけでなく材料も調べる。** 乱れは区切りのファイルの段階で入っていた。完成動画だけを見て、結合の工程が原因だと取り違えた。

## 進め方

- **人が編集するテキストが正。** `digest/` 直下のテキストと `digesta.md` は、ユーザーが手で直している可能性がある。`--fresh` と言われない限り、作り直しや上書きをせず、頼まれた箇所だけを直す。
- 作ったものは自分で見る・聞き取る。画像は PNG を拡大して読む。音声は自分では聞けないので、文字起こしで読みを確かめ、音量は数値で確かめる。そのうえで「耳で確認してほしい点」を報告に書く。
- 中断や拒否のあとは、報告する前にファイルの実体(`ls`、`ffprobe`、`digest.py status`)を確認する。途中まで実行されていたコマンドを「何も変わっていない」と報告してしまったことがある。
- 作業ファイルは `<会議>/digest/work/` に置く。セッション用の一時領域は途中で消えることがある。
- 既存の成果物と同じ名前で出力する前に、上書きしてよいかを考える。別バージョンとして残したい成果物があるなら、`output_dir` 設定で出力先を分ける。
