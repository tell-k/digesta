SQL の実行計画を読もう
発表: ソラさん / PostgreSQL 16 の例・約15分
課題と結果
社内の注文一覧画面の表示が遅い
3.2秒→40ms
遅い原因は画面を見ても分からない。DB が SQL をどう実行したかを見る
EXPLAIN
DB が立てた実行計画を表示する
EXPLAIN ANALYZE
実際に実行し、計画と実測を並べる
見るところは3つ
actual timeどこに時間が
かかっているか
rows推定と実際の
行数のずれ
loops何回
繰り返されたか
注文一覧の改善
Seq Scanorders 約120万行を
全件読み込み
→
複合インデックス(user_id,
created_at)
→
Index Scan実行時間
40ms
  • 推定と実際の行数がずれる → 統計情報が古い。ANALYZE で更新
  • 注意 EXPLAIN ANALYZE は SQL を本当に実行する
    UPDATE / DELETE は BEGIN〜ROLLBACK で挟む
Q
インデックスはたくさん作ったほうがよい?
作りすぎると書き込みが遅くなり、容量も増える。未使用のものは pg_stat_user_indexes で探せる
Q
ORM だと SQL が見えないのでは?
開発環境で SQL をログに出し、EXPLAIN に貼っている
