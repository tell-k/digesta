# ダイジェスト動画の作り方

動画は3つのテキストから作る。どれも `<会議>/digest/` 直下にあり、ユーザーが手で直せる。作例は発表3本の勉強会だが、議題ごとに章を切れば会議にもそのまま使える。

| ファイル | 中身 | 作例 |
|---|---|---|
| `episode.yaml` | 動画の情報。タイトル、章(発表または議題)、色、まとめカードの文言、締めの文言、スライド領域 | `assets/examples/study/episode.yaml` |
| `cuts.yaml` | 元動画から切り出す区間と字幕、話題の題名 | `assets/examples/study/cuts.yaml` |
| `narration.md` | カードで読むナレーション原稿と読み替え | `assets/examples/study/narration.md` |

`digest.py video` は、テキストが変わった部分だけを作り直して結合する。原稿を1行直せば、そのカードの音声合成と撮り直しだけが走る(2〜3分)。

## 目次
1. 動画の構成
2. カットの選び方(cuts.yaml)
3. 動画の情報(episode.yaml)
4. ナレーション原稿(narration.md)
5. 音の設定(声、BGM、整音)
6. ビルドと検証
7. よくある直し

## 1. 動画の構成

```
オープニング
└ 章(発表または議題)ごとに: 章タイトル → 本編(話題ごとの切り抜き) → ポイントまとめ
エンディング(グラレコ全景。グラレコ画像があるときだけ)
締め(終了のあいさつと告知)
```

- 本編は、録画のスライド部分(画面共有がなければ画面全体)を枠の中に置き、右に「いまの話題」、下に字幕を出す。音声は発言者本人の声。
- カード(オープニング、章タイトル、まとめ、エンディング、締め)はアニメーション付きで、ナレーションが入る。
- 目安は全体で 3〜5 分。カード合計が約1分、本編が1章あたり 60〜90 秒。尺の指定がルールにあればそれに従う。章は 2〜4 個が収まりやすい。議題が多い会議は、近い議題をまとめるか、重要な議題だけを章にする。

## 2. カットの選び方(cuts.yaml)

### 手順

1. `work/transcript_*.md`(文字起こし)を読み、章ごとに「これを見れば何の話か分かる」箇所を探す。文字起こしのタイムスタンプが粗い(1分刻みなど)ときは、候補を前後に余裕を持った区間(60〜120 秒)として選ぶ。
2. 候補区間だけを精密に文字起こしする: `asr.py windows <会議> 205-285 430-530 …`。結果は `work/win/<開始>-<終了>.txt` に保存され、画面には件数だけ出る。全文を読まず、`asr.py find <会議> <語> …` で候補の文を探し、`asr.py show <会議> <開始秒> <a-b>` で前後の文だけ読む。全編を起こさないのは、Intel Mac だと実時間より遅いからである。区間が多ければ、コマンドを2〜3本に分けてバックグラウンドで並行実行し、終わるまで 1 回だけ待つ。
3. 文の単位で採用する箇所を決め、`clips` の `start` / `end` にする。発話の頭と語尾が切れないよう、文の開始より 0.1〜0.3 秒前から、終了の 0.1〜0.2 秒後までを取る。前後の発話と重ならない範囲で余白を広めに取るほうが安全。小さく言い始める語(「ただ、」「で、」「こんな」)は文字起こしの開始時刻より前から始まっていることが多い。
4. 字幕(`subs`)を書く。時刻は文字起こしの文の時刻をそのまま使い、文は整える(次項)。長い発話を分けたいときは `asr.py words <会議> <区間> <a> <b>` で単語ごとの時刻を見る。
5. カットした区間のフレームを見て、映っているものを確かめる。`digest.py crop <会議> <秒>` が、画面共有の領域を検出した確認用の画像(縮小版)と crop の値を出すので、これで見え方と切り抜き値を一度に得る。使わない素材(共通ルール参照。個人情報やパスワード。顧客名・案件名は許容)が映っていたら外す。

### 選ぶ基準

- 発表なら、導入(何の話か)、山場(一番面白いところ)、結論やオチ、の3点が入るようにする。質疑に面白いやり取りがあれば1つ入れる。
- 会議の議題なら、論点の提示、決め手になった発言、結論を言っている発言、の3点。決定事項は、決まった瞬間の発言を本人の声で入れると伝わりやすい。
- **ビジネスの会議では、結論が出た話、決定事項、重要な検討事項、次回への TODO・アクションは、必ず動画に入れる。** 尺の目安(3〜5 分)より優先する。多少伸びてよい(ユーザー指示 2026-10-07)。削るのは、雑談、経緯の長い説明、カードで言い換えられる説明的な部分から。議事録の「決定事項」「TODO」の各項目について、本編の切り抜きかまとめカードのどちらかで触れているかを、ビルド前に確かめる。進捗報告の「完了した・依頼中」のような結論も落とさない。
- ナレーションとまとめカードが説明を補えるので、切り抜きは「本人の声で聞く価値がある箇所」を優先する。説明的な部分は削ってカードに任せる。
- 1つの話題(`topics` の1項目)は 10〜40 秒。話題の中で複数の `clips` をつなぐと、その間は短い白フェードになる。
- 話題の題名(`title`)は枠の右側に並ぶ。12字くらいまで。

### 字幕の書き方

- 言い間違い、言い直し、フィラー(えっと、なんか)を取り、読みやすい日本語にする。意味は変えない。
- 文字起こしの誤変換を直す。固有名詞と数字はスライドで確かめる。
- 1行は全角 28 字くらいまで、2行まで。改行は `\N`。
- 文脈が切れて分かりにくいところは丸括弧で補う: `(説明文の生成を)全部やると…`。
- 質疑で話者が替わるところは `Q. …` `A. …` を頭に付ける。

## 3. 動画の情報(episode.yaml)

作例をコピーして書き換える。項目の意味は作例のコメントにある。

YAML の注意: 値に「 #」(空白のあとのシャープ)や「: 」を含むときは引用符で囲む。囲まないと、`thanks: 定例 #12 / おつかれさまでした` は「定例」だけになる(` #` 以降がコメント扱い)。`cuts.yaml` の字幕も同じ。ビルド後にカードのフレームを見て、文言が欠けていないか確かめる。

- `chapters[].who` / `face`: 発表者や担当。議題だけの章では書かない(顔の代わりに `deco` の先頭のイラストが出る)。そのときは `short` に短い名前を書くと、画面右上の進行表示に使われる。
- `chapters[].crop`: 録画のうちスライドが映っている領域(`幅:高さ:左:上`)。書かなければ画面全体を使う(画面共有のない、参加者の顔だけの録画はこれでよい)。画面共有のしかたは人によって違うので、章ごとに調べる。`digest.py crop <会議> <秒>` が黒帯から共有画面の領域を検出して値を出す。うまく検出できないときだけ `digest.py grid <会議> <秒>` で 100px 間隔のグリッド付きフレームを出し、四隅を読む。ブラウザの枠やブックマークバー、スライド編集画面のサムネイル欄は外す。16:9 でなければ左右か上下に白い余白が付く。1つの発表の途中で画面の構成が変わるなら、`clips` の項目に `crop` を書いて上書きできる。
- `chapters[].title`: 章タイトルカードでは1行に収まるよう自動で縮むが、全角 20 字を超えると小さくなりすぎる。長い題名は短い呼び名を `title` に、正式な題名を `sub`(カード用に改行を入れるなら `sub_card`)に書く。
- `chapters[].color`: グラレコの列の色と揃える。
- `chapters[].face`: グラレコと同じ顔アイコン。
- `chapters[].deco`: 章タイトルカードの飾り。発表の内容を表すイラストを最大4個。
- `chapters[].recap`: まとめカード。3項目まで。`text` は 1 行に収まる長さ(全角 22 字くらい)で、`<mark>` を1か所。`sub` は補足。
- `ending`: グラレコ全景を見せるカード。先に `image` を済ませておくと入る。
- サムネイル: スタイルの `cards.html` にあるタイトルスライド(`id=thumb`。同梱のスタイルにはまだない)を、動画の先頭フレームに自動で置く。無いスタイルはオープニングカードの完成状態(タイトル・日付・アジェンダが全部出た状態)を使う。停止中のプレーヤーにはこれが映り、再生すると 0.5 秒でオープニングに溶ける。同じ画像を `output/<名前>_サムネイル.png` にも出す(共有の投稿に添える用)。中身は `label`・`series`・`date`・章の `title` で決まるので、何の動画か一目で分かる文言にする。
- `outro`: 締め。`board` を消せば告知なしの締めになる。告知の文言や宛先は、ルールか素材で確認できたものだけを書く。

イラスト名は `lib/doodle.js` の既存のものか、`digest/icons.js` に追加したもの(グラレコの手引きを参照)。

## 4. ナレーション原稿(narration.md)

- 見出しがカード名(`opening` / `ch1` / `recap1` / … / `ending` / `outro`)。カードはあるのに見出しがなければ、そのカードは無音になる。
- 長さの目安: opening は 2〜3 文(8〜10 秒)、章タイトルは 1〜2 文(3〜8 秒)、まとめは 2 文(7〜9 秒)、締めは 1〜4 文。カードの表示時間はナレーションの長さに自動で合う。
- 章タイトルは「誰の、何の話か」(議題なら「何を決める話か」)。まとめは、まとめカードの3項目を言い換えて一息で言える長さにする。カードの文言を読み上げるだけにしない。
- 載せるのは確認できた事実だけ。
- 読み替えは、まずプロジェクトの `digesta.md` の用語集に「読み:」として書く。ここに書いた語は、どの会議のナレーションでも自動で読み替わる。その会議でだけ読みを変える・止めるなら、会議フォルダの `digesta.md` の用語集に同じ語を書く(読みを書かずに語だけ書くと止まる)。英字の略語(PEP → ペップ)、数え方(1本目 → いっぽんめ)、読みが割れる人名や漢字。
- `narration.md` の `## 読み` には、その会議だけの読み替えを書く(日付「10月7日 → じゅうがつなのか」、その回だけの数量、かぎ括弧を読点に替えるなど)。用語集と同じ語を書くと、会議側が勝つ。

## 4b. スタイル

カードと枠の見た目は、設定の `style` で切り替わる(`doodle` / `business`)。テキスト(`episode.yaml` など)は共通で、同じ内容から別の見た目の動画を作れる。詳しくは `references/styles.md`。business ではイラスト名のうち人物(`face` / `sloth`)は表示されず、未知の名前は文書のピクトグラムになる。

## 5. 音の設定

設定は冒頭の `---` で挟んだ欄に書く。プロジェクト共通(`<プロジェクト>/digesta.md`)を、会議ごと(`<会議>/digesta.md`)が上書きする。

| キー | 値 | 説明 |
|---|---|---|
| `external_api` | `ask` / `allow` / `deny` | Gemini に原稿を送ってよいか。`deny` なら narration は say、bgm は none になる |
| `style` | `doodle` / `business` / `pop` / `mono` | 見た目。既定は doodle |
| `narration` | `gemini` / `voicevox` / `say` / `none` | 既定は gemini |
| `voice` | `Leda` など | gemini の声。聞き比べは `digest.py voices <会議> Leda Autonoe Zephyr` |
| `voice_style` | 英文 | gemini への口調の指示 |
| `bgm` | `lyria` / `none` / ファイルのパス | 既定は lyria。手持ちの曲を使うなら会議のディレクトリからの相対パス |
| `bgm_gain` | `0.166` | BGM の基準音量。声がある間は自動でさらに下がる |
| `bgm_prompt` | 英文 | Lyria への曲の指示。空ならスタイルの既定(doodle は明るいウクレレ、business は静かなピアノ) |
| `clean_audio` | `true` / `false` | 元音声の整音 |
| `credit` | 文字列 | 締めカード最下部の表記。voicevox では必須 |

- gemini と lyria は、`external_api: allow` と API キーが要る。キーは、会議かプロジェクトのフォルダの `.env` に `GEMINI_API_KEY=...` と書く(`.env` が最優先。次に環境変数、`~/.config/digesta/gemini.env`)。Lyria は課金が有効なキーでないと使えない。キーがないときは、ユーザーに置き方を案内する(中身は表示しない)。
- voicevox はローカルのエンジンが要る: `docker run -d --name voicevox_digesta -p 127.0.0.1:50021:50021 voicevox/voicevox_engine:cpu-latest`。
- BGM は一度作ると、`bgm_prompt` と `bgm_model` を変えない限り使い回す。ユーザーが聞いて気に入った曲は、`work/` の外にコピーして `bgm: そのパス` に固定しておくと、設定や skill の更新で作り直されない。
- 曲を変えたいときは `digest.py bgm <会議> --force`。

## 6. ビルドと検証

```bash
uv run "$SK/scripts/digest.py" plan <会議>           # 3 つのテキストの検査と、尺の見積もり(ビルドの前に必ず)
uv run "$SK/scripts/digest.py" video <会議>          # 変わった部分だけ作り直して結合
uv run "$SK/scripts/asr.py" check-narration <会議>   # ナレーションの読みを確認
uv run "$SK/scripts/asr.py" check-video <会議>       # 完成動画の音声を文字起こし
```

`plan` は、YAML が読めない箇所(「: 」や「 #」を含む文の引用符忘れ)、章番号の不一致、切り抜き区間の外にある字幕、原稿の見出し漏れを出し、カードと本編の長さを足した尺を見積もる(実測との差は 2% ほど。ナレーション音声がまだないカードは文字数から推定)。尺の調整はこの数字で行い、ビルドしてから削らない。`video` も同じ検査を最初に行い、誤りがあれば止まる。

初回は 20〜30 分かかる(カードは1フレームずつ撮るため、1枚1〜2分)。バックグラウンドで実行し、終わるまで 1 回だけ待つ(その間に他の確認を進める)。

検証は次の順でやる。音は自分では聞けないので、聞き取りと数値で確かめ、残りはユーザーに耳での確認を頼む。

1. **ナレーションの読み**: `check-narration` は原稿と聞き取り結果を並べる。漢字や英字の表記が違うのは当然なので、音として違う箇所だけを見る。Gemini TTS は実行のたびに揺れ、人名の「〜さん」が別の音になったり、「発表者」が「発表書」になった回があった。違っていたら `digest.py narration <会議> --only <カード名> --force` で作り直し、また確かめる。何度やっても直らなければ `## 読み` にひらがなで読みを足す。
2. **カットの切れ目**: `check-video` が、字幕の先頭・末尾の語が聞き取りにない「欠けの疑い」だけを表示する(全文は `work/digest_asr.txt`)。漢字の表記違いによる誤検出もあるので、疑いの箇所は `asr.py show` で前後を読むか耳で確かめる。欠けていたら `start` を 0.2〜0.4 秒前に、`end` を後ろにずらす。
3. **映像**: `digest.py frames <会議>` で、区切り(カードと本編カット)ごとに 1 フレームを抜いた一覧が 1 枚(`work/frames.png`)できる。これを読んで、字幕のはみ出し、枠の崩れ、カードの文字切れ、使わない素材の混入を見る。本編カットの最後のフレームも見たいときは `--all`。自分で抜くときは PNG にする(動画はリミテッドレンジなので、JPEG に直接は書き出せない)。
4. **音量**: `video` の最後に全体の音量が出る。-16 LUFS 前後、ピーク -1 dBFS 以下なら問題ない。
5. **配布先での聞こえ方**: `video` は書き出す前に、音声パケットの時刻が等間隔か、音と映像の長さが合うか、時刻どおりに並べ直しても音量が変わらないかを自動で調べ、外れたら止まる。止まったときは次の「音声を加工するときの決まり」を見る。

### 音声を加工するときの決まり

`digest.py` の音声まわり(フィルタ、結合、ミックス)に手を入れるときは、次を守る。手元では正常なのに Google ドライブのプレビューで声が 12 か所消えたことがある。経緯は `references/rules.md`「配布先での再エンコード」にある。

- **音声の時刻(PTS)は信用しない。** `loudnorm` のように先読みをするフィルタは、出力の冒頭数秒のパケット時刻を乱す。音の中身は正しく並んでいる。フィルタを通したあとは `asettb=1/48000,asetpts=N` で、サンプルの通し番号から時刻を付け直す。
- **`aresample=async=1` は使わない。** 時刻のとおりに音を伸び縮みさせるので、時刻が壊れていると声を捨てて無音を埋める。「時刻をそろえる」修正のつもりで入れると、欠落を音声に固定する。
- **音声は区切りごとに映像の長さへ合わせてからつなぐ。** フィルタを通した音声は映像より数十 ms 短くなることがある。合わせずにつなぐと、後半で音が映像より早くなる(最大 0.7 秒ずれた例がある)。
- **音声のフィルタを足したり順序を変えたりしたら、パケットの時刻を見る。** 完成動画だけでなく、区切りのファイル(`work/seg/*.mkv`)も見る。

  ```bash
  ffprobe -v error -select_streams a -show_entries packet=pts_time,duration_time -of csv=p=0 <ファイル> | head -40
  ```

  時刻の間隔がパケットの長さと合っていれば正常。0.1 秒分のパケットが 0.019 秒きざみで並ぶ、途中で 2 秒以上飛ぶ、といった並びは壊れている。
- **手元の再生で正常でも、配布先で正常とは限らない。** 手元のプレーヤーは時刻を見ずに順に鳴らす。配布先の再エンコードは時刻のとおりに並べ直す。手元でこれを再現するには、`-af aresample=async=1:first_pts=0` を付けて復号した音と、付けずに復号した音の音量を比べる(検査がやっていること)。

## 7. よくある直し

| 依頼 | 直すところ |
|---|---|
| 尺を縮めたい / 伸ばしたい | `plan` で区切りごとの長さを見て、`cuts.yaml` の clip を外す・足す → `plan` で確かめてから `video` |
| ナレーションの言い回しを変えたい | `narration.md` を編集 → `video` |
| 読み間違いがある | 他の会議でも出る語ならプロジェクトの `digesta.md`、その会議の語なら会議フォルダの `digesta.md` か `narration.md` の `## 読み` に足す。または `narration --only 名前 --force` |
| 声を変えたい | 会議の `digesta.md` の `voice` → `video`(全カードの音声と撮影をやり直す) |
| BGM を小さく / 大きく | 会議の `digesta.md` の `bgm_gain` → `video`(結合だけなので2分) |
| BGM をなくす | 会議の `digesta.md` の `bgm: none` → `video` |
| ドライブや Slack のプレビューでだけ音がおかしい | 音質や BGM を疑う前に、上の「音声を加工するときの決まり」の手順でパケットの時刻を見る |
| 言葉の頭が切れている | `cuts.yaml` の `start` を前へ → `video` |
| 字幕を直す | `cuts.yaml` の `subs` → `video` |
