# digesta: 会議ダイジェスト

会議1回分のフォルダ(録画と文字起こし)から、次の3つを作る。

- **議事録**: 決定事項や発表の要点をまとめた文書。Markdown と docx
- **グラレコ画像**: 内容を1枚にまとめた手描き風の画像(4K と 1920)
- **ダイジェスト動画**: 発言者本人の声の切り抜きに、字幕、ナレーション付きのカード、BGM を付けた数分の動画

定例会議、打ち合わせ、勉強会のどれにも使う。見た目は**スタイル**で切り替える(`doodle`: 手描き風でキャラあり、`business`: 白地・ゴシック体・直線でキャラなし、`pop`: カラフルな議事録風で、人物は Gemini の画像生成、`mono`: 黄・黒・グレーの3色)。何度でもやり直せるように、内容はすべてテキストで持ち、ビルドはスクリプトに任せる。エージェントの仕事は、素材を理解してテキストを書くこと、できあがりを確かめること、ユーザーの直しをテキストに反映することである。

## 引数

`$ARGUMENTS`

- 1つ目: 会議のディレクトリ(例 `tech-lunch/012`、`weekly/2026-10-02`)。指定がなければ、どの会議かを尋ねる。
- 2つ目: 作るもの。`minutes`(議事録)、`image`(画像)、`video`(動画)、`all`(全部、既定)。`minutes,image` のように並べてもよい。
- `--fresh`: 既存のテキストを捨てて、素材から書き直す。これがない限り、既存のテキストは残して使う。
- それ以外の文は、直したい内容として読む(「TODO の期限を直して」「まとめカードの2つ目を短く」「docx でも出して」「business スタイルで」など)。

## フォルダ構成

```
<プロジェクト>/                 例: tech-lunch/、weekly/
├── digesta.md                 このプロジェクトの会議すべてに共通の設定・ルール・用語集(人名・用語の表記、読み、聞き違い)  ← 人が編集する
└── <会議>/                    例: 012/、2026-10-02/
    ├── 録画(mp4 など)と文字起こし(docx / vtt / srt / txt / md)   元素材。変更しない
    ├── digesta.md             この会議だけの設定・ルール・用語集。プロジェクトの digesta.md より優先  ← 人が編集する
    ├── digest/
    │   ├── minutes.md         議事録の正本                  ← 人が編集する
    │   ├── grareco.html       グラレコ本体(スタイル別に grareco.<style>.html も可)  ← 人が編集する
    │   ├── icons.js           この会議だけの追加イラスト(スタイル別に icons.<style>.js も可) ← 人が編集する
    │   ├── episode.yaml       動画のカードの文言            ← 人が編集する
    │   ├── cuts.yaml          動画のカット表と字幕          ← 人が編集する
    │   ├── narration.md       動画のナレーション原稿        ← 人が編集する
    │   ├── lib/               描画ライブラリ(自動生成。編集しない)
    │   └── work/              中間ファイル(消してよい)
    └── output/                成果物
```

`digest/` 直下のテキストと `digesta.md` は、ユーザーが手で直している前提で扱う。頼まれていない箇所を書き換えない。`--fresh` のときだけ、素材から書き直してよい。

## スクリプト

```bash
SK="<この SKILL.md があるフォルダの絶対パス>"   # Claude Code では ${CLAUDE_SKILL_DIR}
uv run "$SK/scripts/digest.py" <command> <会議> [options]   # init / status / minutes / image / video / narration / bgm / voices / sheet / grid / crop / frames / plan
uv run "$SK/scripts/asr.py" <command> <会議> [引数]          # windows / show / find / words / full / check-narration / check-video
```

`digest.py --help` と `asr.py`(引数なし)に各コマンドの説明がある。ffmpeg と uv が必要。docx の出力には pandoc も要る。フォントと Chromium は初回に自動で用意される。

## 文脈とトークンを節約する

費用の大半は、長くなった会話の文脈を 1 往復ごとに読み直すことで決まる(出力の量ではない)。次を守る。

- **会議 1 回につき、新しいセッションで始める。** 別の作業の続きで始めない。
- **重い 3 工程は、サブエージェントを使えるならそれに任せる。** カット表を書く、グラレコを書いて描く、完成品を検査する、の 3 つ。文字起こしの全文やフレーム画像が親の文脈に残らない。プロンプトのひな形と、親が何をするかは `references/agents.md`。
- **待ちは 1 回で。** 時間のかかるコマンド(文字起こし、ビルド、音声合成)は、終わるまで待つコマンドを 1 本だけ実行するか、バックグラウンドで実行して完了の通知を待つ。数十秒おきに確認する往復をしない。
- **出力を会話に流さない。** 文字起こしは `asr.py find <語>` と `asr.py show <開始秒> <a-b>` で必要な文だけ読む。フレームの確認は `digest.py frames` の 1 枚で済ませる。画面共有の領域は `digest.py crop` で数値として受け取る(`grid` を何枚も読まない)。グラレコの拡大確認はパネル数ぶんまで。
- **機械的な工程は下のモデルで。** サブエージェントのモデルを選べるなら、カット表を書くサブエージェントと検査のサブエージェントは速くて安いモデル(Claude Code なら `model: sonnet`)で実行する。判断の多い工程(素材の理解、議事録、グラレコ、カードの文言)は親のモデルで行う。
- **ビルドは `digest.py plan` を通してから。** 誤りと尺をビルド前に出すので、ビルドのやり直し(1 回 10〜20 分と、その確認の往復)が減る。
- 節目(議事録ができた、画像ができた)で文脈の圧縮(Claude Code の `/compact` など)を勧められたら受ける。

## 進め方

### 0. 状況をつかむ

1. `digest.py status <会議>` で、何があり、何が古いかを見る。`digest/` がなければ `digest.py init <会議>` を実行する。ひな形の作成、音声の抽出、文字起こしの取り込み(`work/transcript_*.md`)までやる。
2. ルールを読む。下にあるものほど優先する。
   - `references/rules.md`: どの会議にも効く共通ルール。事実の扱い、表記、秘密情報など
   - `<プロジェクト>/digesta.md`: そのプロジェクトの既定の設定、決めごと、用語集
   - `<会議>/digesta.md`: その会議だけの設定、決めごと、用語集
   人名・サービス名・技術用語の表記と読み、文字起こしの聞き違いは、まず `digesta.md` の「## 用語集」を見る。同じ語は会議フォルダのものが優先。
3. プロジェクトで初めて使うとき(`digesta.md` が `init` で作られたばかりのとき)は、会議の種類と表記の決まりを素材から読み取って `digesta.md` に書いておく。次の会議から同じ判断をせずに済む。
4. 依頼がどれに当たるかを決める。
   - **テキストがまだない、または `--fresh`** → 1 から順に作る。
   - **テキストがあり、ユーザーが手で直した(「直したので作り直して」)** → テキストには触らず、ビルドと確認だけをやる。
   - **テキストがあり、直しを頼まれた** → 該当するテキストだけを直して、ビルドする。どのファイルを直せばよいかは、各手引きの「よくある直し」にある。
   - **議事録の形式だけ変えたい** → `digest.py minutes <会議> --format docx`(または `both`)。
   - **声のサンプル** → `digest.py voices <会議> 声の名前…` を実行し、ファイルの場所を伝える。動画は触らない。
   - **スタイルを変えたい(「business で」「硬い感じに」「キャラなしで」「カラフルに」)** → `references/styles.md` を読む。pop ならキャラクターの定義(`digest/chars.yaml`)を書いて `digest.py chars` で生成してから、画像と動画を作る。設定の `style` を変え、グラレコはそのスタイル用に書き直す(`grareco.<style>.html`)。動画はカードと枠を撮り直すだけで済む。

途中で確認を挟まず、最後まで作ってから見せる。直しは速いので、先に全体を見てもらうほうが早い。止めるのは、次の「外部送信の確認」と、API キーがない、録画が複数あってどれか特定できない、といった先に進めない場合だけにする。録画がないことは止める理由にならない(動画はスライドで作る)。

### 外部送信の確認(動画を作るとき)

動画の既定は、ナレーションが Gemini TTS、BGM が Lyria で、ナレーション原稿と音楽の指示が Google に送られる。会議の内容は社外秘のことがあるので、プロジェクトごとに一度だけ確認する。

- `digesta.md` の設定の `external_api` が `ask` のままだと、スクリプトは音声を作る前に止まる。
- そのときはユーザーに「ナレーション原稿(会議の要約 10 文ほど)と音楽の指示を Google の Gemini API に送ってよいか」を尋ね、答えを `digesta.md` の冒頭の設定に `external_api: allow` か `external_api: deny` として書く。日付と一言の経緯もコメントに残す。
- `deny` のときは、ナレーションは macOS の音声、BGM なしで作る。ローカルで高品質な声を使いたいなら VOICEVOX(クレジット表記が必要)を案内する。
- 議事録と画像は外部に何も送らないので、この確認は要らない。確認待ちの間も、議事録と画像は先に仕上げる。

### 1. 素材を理解する

- `work/transcript_*.md`(文字起こしや会議メモ)と、あれば要約ファイルを読む。文字起こしがない録画は、`asr.py full <会議>` で全編を一から起こす。録画の長さと同じかそれ以上かかり、話者の区別もないので、始める前にユーザーにかかる時間の目安を伝え、バックグラウンドで実行する。途中で止めても、同じコマンドをもう一度実行すれば続きから起こす(最初からなら `--force`)。
- 録画に映像があれば `digest.py sheet <会議>` で全編のコンタクトシートを作り、画面を見る(1 枚だけ)。議題や発表の区切り、スライドの見た目、使えない画面(個人情報やパスワードが映る画面)の位置をつかむ。画面共有の切り抜き値は `digest.py crop <会議> <秒>` で数値として受け取る。
- 会議の種類を見分ける。議題を順に話し合う会議か、発表が並ぶ勉強会か。章(議事録の節、グラレコの列、動画の章)は、議題ごとか発表ごとに切る。
- 事実を確かめる。メモや要約の数値・固有名詞・決定事項は、スライドのフレームか `asr.py windows` の文字起こしで裏を取る(結果はファイルに保存される。`asr.py find <語>` で該当の文だけ読む)。食い違いと、文字起こしだけが根拠の人名は控えておき、最後に報告する。文字起こしの聞き違いは用語集の「聞き違い:」で直す。
- 分かったことのうち、この会議に固有の決めごと(使わない区間、素材の誤り、その回だけの事実)は `<会議>/digesta.md` の「## 用語集」より前に書き足す。
- 人名・用語の表記、読み、聞き違いは `digesta.md` の「## 用語集」に箇条で書き足す(ルールの節には書かない)。次の会議でも使う知見ならプロジェクトの `digesta.md`、その会議でだけ違う(同じ聞き違いが会議によって別人を指す、その回だけ読みを変えたい)なら会議の `digesta.md` の用語集。ユーザーに表記や読みを直されたときも同じ。メモ(子の箇条)に根拠と日付を書く。文字起こしだけが根拠の語は「要確認」の表に入れる。

### 2. 議事録を作る(minutes / all)

`references/minutes-guide.md` を読んでから `digest/minutes.md` を書き、`digest.py minutes <会議>` で出力する。3つの中で一番早くできるので、最初に作る。画像と動画の内容も、ここで整理した事実をもとにする。

### 3. 画像を作る(image / all)

この工程はサブエージェントに任せる(`references/agents.md` の B)。親は章立てと色、「2a. 書く前に抜き出す」の表を渡し、返ってきた数字・固有名詞の一覧を素材と突き合わせる。自分で書く場合は `references/grareco-guide.md` を読んでから `digest/grareco.html`(と必要なら `icons.js`)を書き、`digest.py image <会議>` で描画する。書く前に、手引きの「2a. 書く前に抜き出す」の表を埋め、章ごとの構造を決める。Slack のスレッドに章ごとに貼りたいと言われたら `--split` を付ける(章ごとの 16:9 画像 `<名前>_graphic_chN.png` も出る)。出力を拡大して読み、収まりと誤りを直す。動画も作るなら、先に画像を済ませる(動画のエンディングに使うため)。

### 4. 動画を作る(video / all)

`references/video-guide.md` を読んでから `episode.yaml` と `narration.md` を書く。`cuts.yaml` はサブエージェントに任せる(`references/agents.md` の A。章立てと「必ず入れる内容」の一覧を渡す)。揃ったら `digest.py plan <会議>` で 3 つのテキストの誤りと尺の見積もりを確かめ(誤りがあれば直す。尺は見積もりの段階で調整する。ビルドは 1 回 10〜20 分かかる)、`digest.py video <会議>` でビルドする。会議(定例・打ち合わせ)なら、議事録の決定事項・TODO・結論の出た論点がすべて動画(切り抜きかまとめカード)に入っているかを、カット表を書き終えた時点で突き合わせる。尺より優先する。変わった部分だけを作り直す。初回は 20〜30 分かかるので、バックグラウンドで実行する。録画がない(文字起こしやメモだけ、または音声だけ)ときも動画は作る。`cuts.yaml` の話題を、切り抜き(`clips`)の代わりにスライド(`slide`)で書き、その話題のナレーション原稿を `narration.md` の `## t章-話題`(例 `## t1-1`)に書く。スライドが本編の枠に映り、原稿がナレーションと字幕になる。書き方は `references/video-guide.md`「2b. 録画がないとき」。

### 5. 確かめる

できあがりは必ず自分で確かめる。手順は各手引きの「確認のしかた」にある。要点は次のとおり。

- 議事録は、決定事項・TODO・数値・人名を素材と突き合わせる。
- 画像は拡大して文字を読む。
- ナレーションは `asr.py check-narration` で読みを確かめ、違っていれば作り直す。
- 完成動画は `asr.py check-video` でクリップの切れ目が音の途中に掛かっていないかを確かめ(疑わしい切れ目だけが出る)、`digest.py frames` の 1 枚で映像を見る。この検査もサブエージェントに任せられる(`references/agents.md` の C)。
- `digest.py video` が検査で止まったら(音声の時刻が不連続、音と映像の長さが合わない、時刻どおりに再生すると音が欠ける)、検査を外したり緩めたりせず原因を直す。この検査は、Google ドライブや Slack のプレビューで声が消える不具合を出荷前に止めるためのもの。
- エンディングのカードはグラレコ画像を映すので、画像がまだ無いと省かれる。動画の長さやカードの並び(`work/timeline.txt`)が前回と違っていないかを見る。

不具合を直したときの確かめ方は別に決まりがある(`references/rules.md`「不具合を直すとき」)。

### 6. 報告する

次を短く伝える。

- 成果物の場所(動画は尺も)
- 今回作り直した部分
- 素材と食い違っていた事実、文字起こしだけが根拠の人名や固有名詞(要確認)
- 映してよいか迷った素材(顧客の資料、ドメイン、社名など)の一覧。1 件ずつではなく、ここでまとめて聞く(`references/rules.md`「使わない素材」)
- `digesta.md` の用語集に足した・直した語
- 耳で確認してほしい点(声の抑揚、BGM の音量、整音の効き具合。エージェントは音を聞けない)
- 配布先(Google ドライブや Slack)にアップしたあと、プレビューで一度聞いてもらうこと。手元で正常でも、配布先の再エンコードでだけ出る問題がある
- 直したいときに編集するファイル(議事録なら `digest/minutes.md`、原稿なら `digest/narration.md`、字幕やカットなら `digest/cuts.yaml`、人名・用語の表記や読みなら `digesta.md`。その会議だけなら会議フォルダの `digesta.md`)
