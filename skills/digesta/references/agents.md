# サブエージェントに任せる工程

長い文脈を毎回読み直すことがトークン消費の大半を占める(ある開発定例では 1 往復あたり約 45 万トークン、159 往復で約 7,200 万トークンの読み直しになった)。文字起こしの全文やフレーム画像を親の文脈に残さないために、次の 3 つの工程はサブエージェントに任せ、親は「できたファイル」と短い報告だけを受け取る。Claude Code なら Agent ツール(`subagent_type: general-purpose`)、ほかのエージェントでもサブエージェントやタスクを別の文脈で起動できるなら、その機能を使う。使えないエージェントでは親が自分でやり、文字起こしやフレームは必要な部分だけを読む。

親がやること: 素材の全体像をつかむ(`sheet` 1 枚と文字起こしの流し読み)、章立てと方針を決める、会議の `digesta.md` / `minutes.md` / `episode.yaml` / `narration.md` を書く、ビルドを実行する、結果を報告する。
サブエージェントがやること: 文字起こしを読み込んでカット表を書く、グラレコを描いて確かめる、完成品を検査する。

サブエージェントは skill の文脈を持たないので、プロンプトに「読むべきファイル」と「返すもの」を明示する。モデルを選べるなら、A(カット表)と C(検査)は速くて安いモデル(Claude Code なら `model: sonnet`)にする(機械的な工程で、親のモデルを使う理由がない)。B(グラレコ)は文章と配置の判断が多いので、親と同じモデルにする。

共通の前置き(どのプロンプトにも付ける):

```
作業フォルダ: <会議のディレクトリの絶対パス>
skill: <skill のフォルダの絶対パス。SKILL.md の SK と同じ>
最初に skill の references/rules.md と、プロジェクトの digesta.md、<会議>/digesta.md(どちらも設定・ルール・人名と用語の用語集。会議のほうが優先)を読むこと。
API キーのファイルや .env の中身は表示しない。元素材(録画、文字起こし、メモ)は変更しない。
```

## A. カット表(cuts.yaml)を書く

渡すもの: 章立て(章番号、題名、話者、各章で必ず入れる内容)。会議なら、議事録の決定事項・TODO・結論の一覧。切り抜きの候補になりそうな時刻の目安(文字起こしの見出しから)。

```
目的: <会議>/digest/cuts.yaml を書く。録画がない会議は、このサブエージェントを使わず親が slide で書く(references/video-guide.md「2b. 録画がないとき」)。
手順:
1. skill の references/video-guide.md「2. カットの選び方」と「字幕の書き方」を読む。
2. <会議>/digest/work/transcript_*.md を読み、章ごとに候補区間を決める。
3. 候補区間を精密に文字起こしする: uv run <skill>/scripts/asr.py windows <会議> 205-285 430-530 …
   結果はファイルに保存される。全文を読まず、asr.py find <会議> <語> と asr.py show <会議> <開始秒> <a-b> で必要な文だけ読む。
   区間はすべて 1 本のコマンドに並べ、バックグラウンドで実行して終わるまで 1 回だけ待つ(数十秒おきに確認しない)。コマンドを分けて並行実行しない(CPU を奪い合ってかえって遅くなり、PC も重くなる)。
   会議フォルダに vtt / srt があれば、文字起こしせずにその時刻を使うので数秒で終わる。
4. 切り抜きの区間のフレームを確かめる: uv run <skill>/scripts/digest.py crop <会議> <秒> で画面共有の領域と見え方が分かる(確認用の画像が出る)。顧客名・案件名が映るのは許容。個人情報だけ外す。
5. cuts.yaml を assets/templates/cuts.yaml の形式で書く。必ず入れる内容(渡した一覧)がすべて切り抜きに入っているかを確かめる。
6. uv run <skill>/scripts/digest.py plan <会議> を実行し、誤りを直す。注意(字幕の長さなど)も直せるものは直す。尺が目安(渡された値)を大きく超えるなら、雑談・経緯の説明から削る。決定事項・TODO・結論は削らない。
返すもの: 章ごとの話題と合計秒数、入れられなかった「必ず入れる内容」とその理由、文字起こしだけが根拠の人名・固有名詞、画面共有の切り抜き値(episode.yaml の crop に使う)。cuts.yaml の中身は返さない(ファイルを見る)。
```

## B. グラレコ(grareco.html)を書いて描く

渡すもの: `minutes.md` の場所、スタイル名、章立てと色、「2a. 書く前に抜き出す」の表(親が埋めたもの。空なら自分で埋めさせる)。

```
目的: <会議>/digest/grareco.html を書き、uv run <skill>/scripts/digest.py image <会議> で描画し、収まりと誤字を直す。
手順:
1. skill の references/grareco-guide.md(doodle / mono)か references/styles.md の該当スタイルの節を読む。作例は assets/examples/study/grareco.html(doodle)。business などは skill の assets/styles/<スタイル>/grareco-base.html の雛形を見る。
2. minutes.md をもとに HTML を書く。
3. image を実行し、コンソールの余白・はみ出しの表示を見て直す。
4. 出力の 1920 版を 1 枚読み、全体のバランスを見る。文字の誤りは 4K 版をパネルごとに切り出した画像で確かめる(パネル数ぶん。それ以上は読まない)。
返すもの: 直した点、載せた数字・固有名詞の一覧(親が素材と突き合わせる)、気になる点。HTML の中身は返さない。
```

## C. 完成品を検査する

渡すもの: 会議のディレクトリ。動画のビルドは親が終えていること。

```
目的: 完成動画とナレーションを検査し、直すべき箇所だけを報告する。
手順:
1. uv run <skill>/scripts/asr.py check-narration <会議>: 原稿と聞き取りを比べ、音として違う箇所だけ挙げる(漢字・英字の表記違いは無視)。
2. uv run <skill>/scripts/asr.py check-video <会議>: クリップの切れ目のうち、音の途中で切れている疑いのある箇所が、近くの無音の時刻つきで出る。疑いの多くは耳では問題ない(切れ目のフェードでなじむ)ので、自分では直さず、疑いの箇所を「耳で確認してほしい点」として返す。
3. uv run <skill>/scripts/digest.py frames <会議>: 区切りごとのフレームが 1 枚になる。これ 1 枚を読んで、字幕のはみ出し、枠の崩れ、カードの文字切れ、使わない素材の混入を見る。必要なときだけ --all で本編カットの最後のフレームも見る。
返すもの: 直すべき箇所の一覧(どのファイルのどこを、どう直すか)。問題がなければ「なし」。聞き取りの全文やフレームの説明は返さない。
```

## 待ち方

- 時間のかかるコマンド(文字起こし、ビルド、音声合成)は、終わるまで 1 回のコマンドで待つ。`run_in_background` で実行し、完了の通知を待つか、`until [ -s 結果ファイル ]; do sleep 10; done` のような 1 本の待ちコマンドにする。
- 数秒〜数十秒おきに「終わったか」を確かめる往復をしない。1 往復ごとに会話の全文脈を読み直すので、確認 10 回で 1 本の長い作業と同じだけ消費する。
- 並行して進められる作業(議事録を書く、グラレコを書く)があるなら、待たずにそちらを進める。
