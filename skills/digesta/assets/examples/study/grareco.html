ソラさん PostgreSQL 16 の例で
SQL の実行計画を読もう
EXPLAIN で
遅い SQL の原因を探す
遅い…
課題
注文一覧画面の表示に3.2秒かかる
でも原因は、画面を見てもわからない
どこが
遅いの…?
道具
DB が SQL をどう実行したかを見る
EXPLAIN = 実行計画を表示
EXPLAIN ANALYZE = 実際に実行して実測も
見るところは
3つだけ
時間(actual time)
推定と実際の行数(rows)
繰り返し回数(loops)
推定と実際がずれていたら統計情報が古いかも。ANALYZE で更新する
改善3.2秒 → 40ms!
orders 約120万行を Seq Scan(全件の読み込み)していた
(user_id, created_at) の複合インデックスを作成
Seq Scan→Index Scan に変わった
注意
EXPLAIN ANALYZE は本当に実行する
UPDATE や DELETE は BEGIN と ROLLBACK で挟む
Q
インデックスは多いほどいい?→作りすぎると書き込みが遅い
使われていないものは pg_stat_user_indexes で探せる
Q
ORM だと SQL が見えないのでは?
→ 開発環境で SQL をログに出して、EXPLAIN に貼る
