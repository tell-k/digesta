# 議事録の作り方

`<会議>/digest/minutes.md` が正本。これを書き、`digest.py minutes <会議>` で `output/` に出す。ユーザーが正本を手で直したら、同じコマンドを実行するだけで出力に反映される。

## 出力形式

| 形式 | 指定 | 出力 |
|---|---|---|
| Markdown | `--format md`(既定) | `output/<会議名>_summary.md` |
| Word | `--format docx` | `output/<会議名>_summary.docx` |
| 両方 | `--format both` | 上の2つ |

- 既定は設定の `minutes_format`(プロジェクトか会議の `digesta.md` の冒頭)。ユーザーが「docx でも」「Word で」と言ったら `--format` で指定する。今後もずっとその形式がよいと分かったら、設定のほうを書き換える。
- docx は pandoc で変換する。体裁(日本語フォント、見出しの色、表の罫線)は skill の `assets/reference.docx` で決めている。体裁を変えたいと言われたら、このファイルを Word で開いてスタイルを直してもらう。
- docx にしたときに崩れやすいのは、入れ子が3段以上の箇条書き、表の中の改行、HTML タグ。正本では使わない。

## 型を選ぶ

会議の種類で型が違う。ひな形は `assets/templates/` にある。プロジェクトのルールに型の指定があればそれに従う。

### 会議・打ち合わせ(`minutes-meeting.md`)

読む人が知りたいのは「何が決まり、誰がいつまでに何をするか」なので、それを先頭に置く。

1. 開催情報(日時、場所、出席者)
2. **決定事項**: 番号付きで、1項目1文。「検討する」「調整する」は決定ではないので、持ち越しに書く
3. **TODO**: 表(内容、担当、期限)。担当か期限が録画で言われていないものは空欄にせず「未定」と書く
4. 議題ごとの記録: 要点、出た意見、結論。誰の意見かが大事な場面だけ発言者を書く
5. 持ち越し・未決事項
6. 次回(録画で確認できたときだけ)
7. 要確認(下記)

### 勉強会・発表会(`minutes-study.md`)

決定事項がないので、発表の中身が伝わることを優先する。作例は `assets/examples/study/minutes.md`。

1. 開催情報
2. 概要(全体を 2〜3 文)
3. 発表ごと: 概要、ポイント(箇条書き 4〜7 個)、質疑(Q. / A.)
4. 連絡事項
5. 要確認

どちらにも当てはまらない会議(1on1、インタビュー、ワークショップ)は、近いほうの型をもとに節を組み替える。

## 書き方

- **事実だけを書く。** 決定事項、TODO、数値、日付は、録画の発言かスライドで確認できたものに限る。メモや自動要約にしか出てこないものは、文字起こしで裏が取れなければ載せない。裏が取れないが重要そうなものは「要確認」に書く。
- **発言を要約しすぎない。** 「◯◯について議論した」では何も伝わらない。何が論点で、どういう意見が出て、どう落ち着いたかを書く。
- **1項目1文、主語と目的語を省かない。** 議事録は、会議に出ていない人が数か月後に読む。「あれは来週やる」ではなく「負荷試験の見積もりは、佐藤さんが 10/9 までに出す」。
- 人名の表記はルールに従う(姓+さん、ニックネームなど)。出席者は、録画の参加者表示や文字起こしの話者名で確認する。`digesta.md` の用語集で「聞き違い:」に挙がっている語は、その語の表記に直す。自動文字起こしの本文に出てくる人名は聞き違いが多いので、話者名や画面表示で裏が取れないものは「要確認」に入れる。
- 雑談、言い間違い、個人的な話は載せない。ただし勉強会の自己紹介のように、それ自体が発表の中身なら載せる。
- 機微な話題(人事、評価、顧客名、金額)は、ルールに指示がなければ載せる前に確認事項として報告に挙げる。
- 時刻は必要なときだけ書く。録画の該当箇所を示したいときは「(12:30 ごろ)」のように添える。

## 「要確認」の節

文字起こしだけが根拠の人名・固有名詞・数値、聞き取れなかった箇所を、最後の節にまとめる。読んだ人が確認して直せるようにするためである。確認が取れたらユーザーがこの節を消す。該当がなければ節ごと書かない。

報告でも同じ内容を伝える。

## 確認のしかた

- 決定事項と TODO の1件ずつについて、根拠になった発言を文字起こしで指させるかを確かめる。指させないものは消すか「要確認」に移す。
- 人名、数値、日付を素材と突き合わせる。
- docx を出したときは、`pandoc <docx> -t plain` で本文が欠けていないか、見出しの段が正本どおりかを見る。

## よくある直し

| 依頼 | やること |
|---|---|
| 文言を直したい | `digest/minutes.md` を直して `minutes` |
| docx でも欲しい | `minutes --format both` |
| いつも docx で出したい | `digesta.md` の `minutes_format: both` か `docx` |
| TODO を先頭にしたい、節の順を変えたい | 正本の節を並べ替える。いつもそうしたいなら `digesta.md` の「議事録」に書く |
| もっと短く / 詳しく | 正本を書き直す。分量の好みは `digesta.md` に書いておく |
